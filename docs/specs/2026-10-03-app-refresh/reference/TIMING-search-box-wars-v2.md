# Timing plan: search-box-wars-v2 (Shorts cut)

Generated by `src/timing/timing.mjs` (`computeTimingPlan`, a reusable module) via `src/sv2/make-plan.mjs` **before** rendering. The composition reads `timing-plan.json` and maps frame → month through `makeTimeMap(knots)` (monotone cubic, so speed never jumps).

## Strategy
1. **Measure change density per month** from the real data (StatCounter, 213 months):
   `score(month) = Σ weighted rank inversions among the visible top 9 challengers (row weight 1/(1+0.18·row), using the sticky 3-month-average order the viewer sees) + 1.5 × entries/exits of the top-10 board + Σ|Δshare| / 6 % (bar movement on the 0–6 % axis) + 0.1 base`.
2. **Frames ∝ score**: each month gets frames in proportion to its score, clamped to 1–10 frames/month, Gaussian-smoothed (σ = 1.5 months) so the speed curve has no jerks, then renormalised to the timeline budget (810 frames = 27 s).
3. **Dwell bumps** (Gaussian, extra frames) around story events so the evidence cards can be read.
4. **Result**: on-screen changes per second become close to even. Coefficient of variation of changes/sec across months: **0.539 with uniform time → 0.206 warped** (excluding the deliberate dwell slow-downs; 0.421 including them).
5. **2011–2016 flicker**: Bing and Yahoo trade #2 almost monthly, and the 0.05–0.3 % tail reshuffles constantly. The order is driven by a **3-month centred moving average plus hysteresis**: an engine overtakes its neighbour only when ahead by 6 % of the value + 0.01 pt (`stickyOrders` in the module). It is labelled on screen ("ORDER: 3-MO AVG" plus a source note). Bar lengths and numbers stay raw monthly values. Top-10 row changes over 213 months: **575 raw → 402 with the 3-month average → 257 with hysteresis**. A 10-frame easing kernel then animates each swap. The plan's change score uses the same order the viewer sees (`plan.orders`, which the video reads).

## Long-form note
A long-form YouTube cut would run the same plan ×3 slower: timeline ≈ 81 s, total ≈ 1:50–2:00 with longer card holds. Not rendered.
Re-running `computeTimingPlan` with a 3× longer `startFrame→endFrame` budget gives the same curve shape; the long cut would also lift `minFrames` so quiet years stay readable, and hold each card ~3 s. **Only the Short was rendered.**

## Reuse
```js
import { computeTimingPlan, makeTimeMap } from "./timing/timing.mjs";
const plan = computeTimingPlan({ periods, entities, value: (entity, i) => share, startFrame: 60, endFrame: 870,
  topN: 9, axisMax: 6, rankSmooth: 1, hysteresis: { rel: 0.06, abs: 0.01 }, events, minFrames: 1, maxFrames: 10, sigma: 1.5,
  weights: { rank: 1, value: 1, base: 0.1, entry: 1.5 } });
const tm = makeTimeMap(plan.knots); // tm.at(frame) -> fractional period, tm.frameOf(period) -> frame
```
