Generated by `computeTimingPlan` (@statreel/compositions) **before** rendering. sha256 `a01c2c71f3e0f976ed9a45f8a3fe894608a600dcae07c88e7b1cd4fc143a9fb5`.
The composition reads the plan and maps frame -> period through a monotone cubic time map, so speed never jumps.

## Strategy
1. **Measure change density per month**: `score = sum of weighted rank inversions among the visible top 10 (row weight 1/(1+0.18 x row), using the order the viewer sees) + 1.5 x entries/exits + sum of |delta value| / 109.6 (bar movement on the axis) + 0.1 base`.
2. **Frames proportional to score**: clamped to 2.526-26.274 frames per month, Gaussian-smoothed (sigma = 1.5), renormalised to the timeline budget (960 frames = 32.0 s).
3. **Dwell bumps** (Gaussian, extra frames) around the events so the cards can be read.
4. **Order**: 3-period centred moving average + hysteresis (an entity overtakes only when ahead by 6% of the value + 0.1863). Labelled on screen: "ORDER: 3-MO AVG".
5. **Evenness** (coefficient of variation of changes per second across groups): 0.372 with uniform time, 0.176 warped (excluding the deliberate dwell), 0.267 including dwell.
